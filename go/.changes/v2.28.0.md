([#3570](https://github.com/x402-foundation/x402/pull/3570)) - Thanks [@phdargen](https://github.com/phdargen) and [@cursoragent](https://github.com/cursoragent)!
- >- Add optional SchemeNetworkClient PaymentCreationFailureHandler so schemes can recover from a failed CreatePaymentPayload after user hooks. Introduce WithPaymentRequired to attach the full 402 challenge on context; HTTP PaymentRoundTripper and MCP clients pass it when retrying after OnPaymentResponse recovery so handlers can fall back to a sibling accept (for example client-signed batch-settlement when server-signed is untrusted). Centralize hook and scheme recovery in recoverCreationFailure; extend PaymentCreationFailureContext with PaymentRequired. ([#3603](https://github.com/x402-foundation/x402/pull/3603)) - Thanks [@phdargen](https://github.com/phdargen) and [@cursoragent](https://github.com/cursoragent)!
- >- Implement Go batch-settlement for Solana (client, server, facilitator) on paymentchannels: cumulative client-signed vouchers and server-signed operator metering with trust policy and PaymentCreationFailureHandler fallback to client-signed accepts; channel manager, pending settlement, seal and distribute, recovery, receiver binding and authorizer stores, delegated receiver auth, and refund/close flows. Document imports and modes in go/mechanisms/svm/batch-settlement/README.md. Expand Go batch-settlement examples (client, server, facilitator signers) and e2e SVM batch coverage. ([#3603](https://github.com/x402-foundation/x402/pull/3603)) - Thanks [@phdargen](https://github.com/phdargen) and [@cursoragent](https://github.com/cursoragent)!
### Changed
- >- Refactor SVM upto onto shared paymentchannels: move open, settle, close, reclaim, rent cleanup, discovery, and facilitator channel work out of upto/facilitator; replace hand-rolled instructions with codegen-generated payment-channels client types and builders; add onchain helpers, PaymentChannelFacilitatorSigner with AssertPaymentChannelFacilitatorSigner, and an LRU channel-PDA cache (4096 entries). Upto client uses shared svm ResolveBlockhash and ResolveOpenSlot and paymentchannels requirement helpers. Extend FacilitatorSvmSigner with SimulationRPCOpts and an optional simulate-transaction options argument (breaking for custom signers); add optional FacilitatorConfirmedTransactionReader and blockhash-validity caps for batch-style recovery. Regenerate payment-channels client via updated codegen script and CI check. Delegate upto rent cleanup to paymentchannels RentCleanupManager. ([#3603](https://github.com/x402-foundation/x402/pull/3603)) - Thanks [@phdargen](https://github.com/phdargen) and [@cursoragent](https://github.com/cursoragent)!
- >- Unify SVM upto and batch-settlement facilitator channel storage on paymentchannels.PaymentChannelStorage. Opens and activity are recorded before broadcast and a failed write does not broadcast. A failed open is reverted; activity is kept. The receiver-authorizer binding and delegated caller identity live on that row. Upto ChannelStorage, DelegatedAuthStore, and the batch receiver-authorizer and delegated-auth stores are removed. Delegated mode requires a caller-identity callback and writes that identity on the same channel row. ([#3603](https://github.com/x402-foundation/x402/pull/3603)) - Thanks [@phdargen](https://github.com/phdargen) and [@cursoragent](https://github.com/cursoragent)!
