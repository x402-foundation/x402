- Add the auth-capture EVM scheme server and facilitator (delegated and custom operators, escrow and authorization flows, sync and deferred capture, partial capture, refunds, lifecycle manager and storage, merchant-configurable route extras, minute-bucketed dynamic deadlines), typed escrow revert mapping, and Go examples alongside the existing client. ([#3622](https://github.com/x402-foundation/x402/pull/3622)) - Thanks [@CarsonRoscoe](https://github.com/CarsonRoscoe) and [@cursoragent](https://github.com/cursoragent)!
- 'Add facilitator-authored settlement metadata (`m`) to the builder-code ERC-8021 Schema 2 suffix: `evm.DataSuffixContext.Metadata`, `BuilderCodeSuffixData`, and `m` support in `EncodeBuilderCodeSuffix` and `ParseBuilderCodeSuffixFromCalldata`. `EncodeBuilderCodeSuffix` now takes `BuilderCodeSuffixData` and returns an error when the CBOR exceeds 65,535 bytes.' ([#3666](https://github.com/x402-foundation/x402/pull/3666)) - Thanks [@phdargen](https://github.com/phdargen)!
- 'Add facilitator-delegated receiver authorization to the auth-capture EVM scheme. A server without a ReceiverAuthorizerSigner sends unsigned charge, capture, void and refund payloads (voidRemainder replaces voidAuthorizerSignature) and the facilitator signs them after ResolveCallerIdentity authenticates the caller, binding the identity to the paymentInfoHash in a DelegatedAuthStorage (InMemoryAuthCaptureDelegatedAuthStorage for local use). The server resolves self, delegated or collect-only per route, with Config.CollectOnlyRoutes and ValidateFacilitatorSupport checks. An omitted route receiverAuthorizer no longer implies collect-only: set it to the zero address explicitly. Replace the dedicated auth-capture client example with the base HTTP client example.' ([#3203](https://github.com/x402-foundation/x402/pull/3203)) - Thanks [@phdargen](https://github.com/phdargen) and [@A1igator](https://github.com/A1igator)!
- Add facilitator-managed voucher custody for EVM batch-settlement. extra.voucherManager is "server" or "facilitator" (omitted means "server"; /supported advertises both). extra.delegatedRefund is always emitted on /supported and is true only when the facilitator sets ResolveCallerIdentity. A managed RefundAuthorizerSigner puts extra.refundAuthorizer on the 402; without a signer the server relies on delegatedRefund and omits it. Managed refunds are authorized by a server signature or by caller identity (the facilitator strips client signatures and re-signs). Admission locks use pendingId and release on cancel. chargeCount is attested onchain per claim in ERC-8021 m.x402ChargeCounts and read back with DecodeClaimAttestation. Storage is a shared in-memory, file, and Redis package with worker query helpers. ChannelStorage is Get/List/UpdateChannel CAS-only (blind Set/Delete are removed; breaking for custom storage implementors), pendingRequest is no longer on ChannelSession, and locks live on ChannelLockStorage so durable storage and locks can be mixed. The client accepts a channel salt as a non-negative index or bytes32 hex and packs refundAuthorizer into the salt only for facilitator-managed 402s. World Chain USDC (eip155:480 and eip155:4801) is a default asset. ([#3726](https://github.com/x402-foundation/x402/pull/3726)) - Thanks [@phdargen](https://github.com/phdargen) and [@cursoragent](https://github.com/cursoragent)!
- 'SVM upto: add Config.FacilitatorTransactionVersion and RentCleanupConfig.FacilitatorTransactionVersion to choose the message version (0 or 1) of the claim, cancel, and rent-cleanup transactions the facilitator builds itself. Client-built versions are unaffected. Unset keeps v1.' ([#4017](https://github.com/x402-foundation/x402/pull/4017)) - Thanks [@phdargen](https://github.com/phdargen) and [@cursoragent](https://github.com/cursoragent)!
### Changed
- 'SVM exact: facilitators (current and legacy x402 v1 wire) advertise extra.transactionVersions ([0]) in /supported, servers copy it into PaymentRequirements.extra, clients build an advertised version and refuse a facilitator that accepts none they can build, and verifiers reject any message version other than legacy or 0 with unsupported_transaction_version before inspecting signatures or instructions. Legacy messages remain accepted for backward compatibility but are deprecated and never advertised.' ([#3474](https://github.com/x402-foundation/x402/pull/3474)) - Thanks [@lgalabru](https://github.com/lgalabru) and [@claude](https://github.com/claude)!
- 'SVM upto: negotiate version 0 for client-built opens (an unsupported open message version is rejected with unsupported_transaction_version) while independently building facilitator claim/reclaim transactions as v1 with inline resource limits; the settlement loaded-account-data budget defaults to 4 MiB and is configurable via SettleLoadedAccountsDataSizeLimit; reclaim cleanup now greedily packs against the 4,096-byte wire, 64-account, and 64-instruction ceilings.' ([#3710](https://github.com/x402-foundation/x402/pull/3710)) - Thanks [@lgalabru](https://github.com/lgalabru) and [@claude](https://github.com/claude)!
- Call scheme SettleOnCancel even when no before-handler settle has completed, passing the completed phases so the scheme decides. A failure-path receipt includes a cancel settle only when a before-handler settlement exists; otherwise it echoes that settlement or is omitted. AfterSettleAbortError fails an onchain-successful settle closed (success false, keeping transaction, amount, payer, and onchain extra) on the normal path and the beforeSettle skip path; other afterSettle errors stay non-fatal and are logged. The aborted receipt skips response enrichment and keeps its transaction, amount, and extra in HTTP PAYMENT-RESPONSE and MCP _meta. HTTP PAYMENT-RESPONSE now forwards transaction, amount, and extra from a failed settle response returned by the facilitator, matching TypeScript; thrown settle errors still surface a transaction only for settlement_pending. afterVerify hooks run on a facilitator isValid:false response, while onVerifyFailure runs only on thrown verify errors. SVM upto and auth-capture SettleOnCancel return nothing unless the before-handler settle already completed. MCP rethrows a handler error when there is no failure receipt. ([#3726](https://github.com/x402-foundation/x402/pull/3726)) - Thanks [@phdargen](https://github.com/phdargen) and [@cursoragent](https://github.com/cursoragent)!
- 'SVM batch-settlement: the facilitator advertises transactionVersions ([0]) in /supported, and the client refuses to build deposits, top-ups, or refunds with unsupported_transaction_version when the advertised set excludes every version it can build. The upto facilitator now advertises a copy of the version list instead of the shared slice.' ([#3710](https://github.com/x402-foundation/x402/pull/3710)) - Thanks [@lgalabru](https://github.com/lgalabru) and [@claude](https://github.com/claude)!
- Upgrade the Go SDK minimum Go version to 1.26.10 and bump dependencies (`echo/v4` v4.16.2, `modelcontextprotocol/go-sdk` v1.8.0, `quic-go` v0.64.1, `klauspost/compress` v1.20.3, `otel` v1.47.0, `golang.org/x/net` v0.62.0, `golang.org/x/crypto` v0.58.0, `golang.org/x/sys` v0.49.0, `golang.org/x/text` v0.43.0) to resolve published security advisories. Go 1.24 and 1.25 toolchains no longer build the module without upgrading to Go >= 1.26.10. ([#3984](https://github.com/x402-foundation/x402/pull/3984)) - Thanks [@phdargen](https://github.com/phdargen) and [@cursoragent](https://github.com/cursoragent)!
