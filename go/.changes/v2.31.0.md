## v2.31.0 - 2026-11-12
### Added
- 'Added an optional preflight/postflight instruction-tuple allowlist to the exact SVM facilitator Path 1 (static layout) verifier. Config.PreflightInstructionAllowlist and Config.PostflightInstructionAllowlist let a sponsor accept a fixed, pre-vetted block of extra instructions (by program ID + discriminator) immediately before/after the required protocol instructions - e.g. atomically channeling funds from an out-of-band mechanism into the same transaction as the merchant transfer. Guard (Lighthouse) instructions may be interspersed within a matched block. A matched block is fee-payer-isolation-checked before being accepted. An empty tuple or empty discriminator never matches (fail closed). Both allowlists default to empty, which is a strict no-op - existing behavior is unchanged unless explicitly configured.' ([#3615](https://github.com/x402-foundation/x402/pull/3615)) - Thanks [@CarsonRoscoe](https://github.com/CarsonRoscoe) and [@cursoragent](https://github.com/cursoragent)!
- 'Add Casper Network support: the exact scheme (client, server and facilitator) settling CEP-18 tokens through CEP-3009 transfer_with_authorization, with csprUSD default assets on casper:casper and casper:casper-test, Casper client and facilitator signers for ed25519 and secp256k1 keys, settlement_pending reconciliation and duplicate-settlement protection, plus Casper support in the Go examples and e2e.' ([#3885](https://github.com/x402-foundation/x402/pull/3885)) - Thanks [@davidatwhiletrue](https://github.com/davidatwhiletrue) and [@claude](https://github.com/claude)!
- 'SVM payment-channel rent cleanup: optional `BeforeCloseOrDistribute func(ctx, candidate) error` on `paymentchannels.RentCleanupOptions` and the `upto` and `batch-settlement` `CleanupOptions`, called with `ChannelID`, `Payer`, `PayTo` and `Action` before an abandon-close, forced close or distribute is built. A non-nil error skips the channel, is reported through `OnError`, and does not consume a `MaxClosesPerRun` slot. Reclaim does not call it. Nil keeps the existing behavior; wire format unchanged.' ([#4204](https://github.com/x402-foundation/x402/pull/4204)) - Thanks [@phdargen](https://github.com/phdargen) and [@cursoragent](https://github.com/cursoragent)!

### Fixed
- 'Fixed exact SVM Path 1 rejecting Lighthouse assertion guards before the compute-budget/TransferChecked sequence or beyond the old seven-instruction cap. Identity classification preserves protocol relative order while permitting assertions anywhere without a count cap. Only assertion discriminators 2..=17 are guards, and every guard must isolate the facilitator fee payer. MemoryWrite, MemoryClose, empty data, and unknown variants are rejected without smart-wallet fallback; previously accepted unsafe Lighthouse instructions are intentionally rejected. Configured preflight/postflight blocks cannot hide top-level TransferChecked instructions; their CPI effects remain operator-trusted. Existing error constants remain exported, but Path 1 no longer emits invalid_exact_solana_payload_transaction_instructions_length or invalid_exact_solana_payload_unknown_{fourth,fifth,sixth,seventh}_instruction. Callers must handle invalid_exact_solana_payload_unknown_instruction and invalid_exact_solana_payload_transaction_instructions_order instead. Pending settlements still reconcile their broadcast signature when the supplied fee payer cannot be parsed.' ([#3615](https://github.com/x402-foundation/x402/pull/3615)) - Thanks [@CarsonRoscoe](https://github.com/CarsonRoscoe) and [@cursoragent](https://github.com/cursoragent)!
- 'EVM batch-settlement self-managed mode: `BatchSettlementChannelManager` now claims and refunds only channels bound to its own `Network`, so a manager sharing a store with another network no longer submits or refunds that network''s channels through the wrong facilitator. Claim, `SelectClaimChannels`, refund, idle-refund, `SelectRefundChannels` and `GetWithdrawalPendingSessions` selection are scoped in memory by the persisted `ChannelSession.Network`, falling back to the channel-id binding for rows written without one. Server writes (BeforeVerify/AfterVerify snapshots, AfterSettle deposit and refund commits, managed replica) now stamp `ChannelSession.Network` from the request requirements. `Claim` now continues past a failed batch instead of aborting: it returns the successful batch results together with the joined batch errors, sets pending settle when any batch succeeded, and leaves failed batches claimable for the next pass. `ClaimAndSettle` settles after a partial claim and returns the joined claim and settle errors, and the auto-claim job still reports `OnClaim` for the batches that succeeded. Unchanged on the wire.' ([#4146](https://github.com/x402-foundation/x402/pull/4146)) - Thanks [@phdargen](https://github.com/phdargen) and [@cursoragent](https://github.com/cursoragent)!
- 'MCP: report "Payment cancellation outcome unknown" when cancellation does not produce a receipt, and do not offer another payment.' ([#4151](https://github.com/x402-foundation/x402/pull/4151)) - Thanks [@PhilBot402](https://github.com/PhilBot402) and [@phdargen](https://github.com/phdargen)!
- 'Resource server: a beforeVerify or beforeSettle hook that returns an error now fails closed with before_verify_hook_error / "before verify hook failed" or before_settle_hook_error / "before settle hook failed". ([#4149](https://github.com/x402-foundation/x402/pull/4149)) - Thanks [@PhilBot402](https://github.com/PhilBot402) and [@phdargen](https://github.com/phdargen)!

([#4172](https://github.com/x402-foundation/x402/pull/4172)) - Thanks [@PhilBot402](https://github.com/PhilBot402) and [@phdargen](https://github.com/phdargen)!
- 'SVM batch-settlement facilitator: a settle failure that already broadcast a transaction (settlement_pending, transaction_failed, payout_attribution_ambiguous) is returned as an x402.SettleError carrying the signature instead of a success:false response. Failures before a broadcast, including channel_closing, stay responses. The channel manager maps a SettleError back to the failed response, so claim, seal and distribute behave as before. Wire format unchanged.' ([#4175](https://github.com/x402-foundation/x402/pull/4175)) - Thanks [@phdargen](https://github.com/phdargen) and [@cursoragent](https://github.com/cursoragent)!
- 'Gin middleware: a handler or downstream middleware that writes a 400+ response and then aborts now delivers that response. Previously the abort branch discarded the captured status and body, so the client received an empty 200 while the payment was withheld. Aborts are no longer a special case: settlement is decided by response status alone, so a 400+ response withholds settlement and anything below 400 settles, matching the Echo, net/http and TypeScript adapters. Gin previously never settled an aborted request, so a handler that served a response and aborted now settles where it previously did not. A redirect now reaches the client as its real 3xx status instead of a 200: the response capture ignored the -1 code c.Redirect renders with, recorded it, and dropped the status set by http.Redirect.' ([#4188](https://github.com/x402-foundation/x402/pull/4188)) - Thanks [@mortezashojaei](https://github.com/mortezashojaei)!
- 'Gin, Echo and net/http middleware: the handler-threw, handler-aborted and handler-failed paths now resolve settlement cancellation through one shared helper. A handler that sets settlement overrides no longer leaks the internal Settlement-Overrides header to the client on those paths, and ProcessSettlement now strips it on the before-handler receipt-echo path too, which covers flows such as upfront that never settle after the handler.' ([#4189](https://github.com/x402-foundation/x402/pull/4189)) - Thanks [@mortezashojaei](https://github.com/mortezashojaei)!
