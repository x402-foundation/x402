x402 × ERC-8004 — ticket flow (one contract)

1-step x402 (same URL). One contract: FeedbackGateway. Spec: specs/extensions/erc8004_ticket_v2.md

What we added: one contract

Contract · the gateway

FeedbackGateway

Settles the x402 payment, mints a single-use ticket, then itself submits ticket-gated feedback to the canonical ERC-8004 ReputationRegistry.

  • settleAndMintTicket{EIP3009,Permit2} — pay → mint ticket (binds payer + agentId)
  • submitFeedback — self-paid: payer consumes ticket + calls giveFeedback
  • submitFeedbackFor — sponsored: relayer submits a client-signed FeedbackIntent
  • revokeFeedbackFor — client-signed revoke, relayed to the registry
Canonical · unchanged

ReputationRegistry (v2)

The deployed ERC-8004 registry. Records feedback keyed by msg.sender — which here is always the gateway.

  • No upgrade required; no ticket awareness needed
  • clientAddress == FeedbackGateway for every payment-backed feedback
  • Real payer recovered off-chain (see below)
Why one contract (no EIP-7702). The gateway calls giveFeedback itself, so the registry sees msg.sender == gateway. We give up on-chain per-client attribution and recover the real payer off-chain instead — which removes the EIP-7702 delegate and the second contract entirely. Filtering NewFeedback by clientAddress == FeedbackGateway yields exactly the payment-backed set (unforgeable — no one else can be that msg.sender).
client pays x402 → FeedbackGateway.settleAndMintTicket → Ticket{payer, agentId, agentAddress} client builds artifact + feedbackHash (commits ticketId, payer, agentId) ├─ self-paid: payer → FeedbackGateway.submitFeedback(ticketId, params) └─ sponsored: relayer → FeedbackGateway.submitFeedbackFor(intent, params, sig) (client signs, pays 0 gas) └─ consume ticket → registry.giveFeedback(... feedbackHash) → capture feedbackRef[ticketId] └─ emit TicketConsumed(ticketId, payer, agentId, agentAddress, feedbackHash) revoke: payer signs RevokeIntent → FeedbackGateway.revokeFeedbackFor → registry.revokeFeedback(agentId, idx)

Off-chain payer recovery (aggregators)

The registry event has no payer; recover it by joining on feedbackHash.

1. filter NewFeedback where clientAddress == FEEDBACK_GATEWAY_ADDR (payment-backed set) 2. join NewFeedback.feedbackHash == TicketConsumed.feedbackHash 3. payer = TicketConsumed.payer // the real customer (bound at mint) assert TicketConsumed.agentId == NewFeedback.agentId (on-chain feedbackHash uniqueness makes the join 1:1; verify artifact.settlement.payer == payer)

Counting: enumerate from TicketConsumed (one per consumed ticket), not from NewFeedback. Invariant: payment-backed feedback ≤ tickets consumed ≤ payments made.

Summary

  • Contract: FeedbackGateway — settles x402, mints a single-use ticket, then itself calls giveFeedback on the canonical ReputationRegistry. The registry records clientAddress == FeedbackGateway; real payer recovered off-chain via TicketConsumed.
  • No bind at mint: client signs payment only; settlement is permissionless (gated by the signed authorization), so no facilitator allowlist. agentId is server-sourced at settle (never sent to or echoed by the client) and bound on-chain to the paid address.
  • Attestation: agent signs EIP-712 after handler → X-X402-Interaction-Attestation (best-effort; missing → CLIENT_ONLY).

Feedback paths

Path A — Self-paid: payer calls FeedbackGateway.submitFeedback(ticketId, params) directly → consume ticket + FeedbackGateway calls canonical giveFeedback.
Path B — Sponsored: payer signs an EIP-712 FeedbackIntent; a relayer submits FeedbackGateway.submitFeedbackFor(intent, params, sig) and pays gas. The gateway verifies the signature, consumes the ticket, and calls giveFeedback.

Phases (one paid request)

0 — Discover

GET → 402 advertises the erc8004 extension as a presence marker — no agentId on the wire. The client signs payment only; nothing to echo or confirm.

1 — Sign payment

Standard x402 token authorization (EIP-3009 / Permit2 / ERC-20).

2 — Paid retry

GET + X-PAYMENT → verify → settle.

3 — Settle + mint (one tx)

The server stamps its agentId into the settle requirements (server-sourced, not client-supplied). Facilitator re-verifies the payment (signature, amount, recipient, expiry — same checks as the standard x402 settle), then settleAndMintTicket*(payer, agentId, agentAddress, payment) settles and mints in one tx; the wrapper binds the ticket on-chain (ownerOf(agentId) == payTo). Plain ticket fields stored. ticketId on PAYMENT-RESPONSE.

4 — Serve + attest (best-effort)

Handler runs. Server signs InteractionAttestation from raw request/response bytes. If signing fails: still return 200 without header.

5 — HTTP response

200 + body + PAYMENT-RESPONSE + optional X-X402-Interaction-Attestation.

6 — Feedback (later)

Client builds the artifact (embeds attestation when present), calls FeedbackGateway.submitFeedback (self-paid) or provides a signed FeedbackIntent for a relayer → gateway consumes ticket + calls ReputationRegistry.giveFeedback.

7 — Off-chain verify

verify_feedback: ticket match → attestation field compare → FULL / CLIENT_ONLY / DISPUTED / REJECTED.

Join keys for aggregators. ticketId links TicketMinted ↔ TicketConsumed (ticket lifecycle). feedbackHash links TicketConsumed ↔ NewFeedback — the join recovers payer (see Off-chain payer recovery above). (agentId, clientAddress, feedbackIndex) links NewFeedback ↔ FeedbackRevoked / ResponseAppended. feedbackHash commits the off-chain artifact at feedbackURI (which embeds the agent's InteractionAttestation).
Payment-backed vs direct. The canonical registry is permissionless — anyone can call giveFeedback. Payment-backed feedback = a NewFeedback where clientAddress == FeedbackGateway (only the gateway can be that msg.sender, and it only calls the registry after consuming a valid ticket). That filter is the on-chain signal aggregators use; verify_feedback then checks the ticket + attestation off-chain.
