x402 × ERC-8004 — ticket flow

1-step x402 (same URL). Implemented on branch feat/erc8004-extension (Phases 1–5 done). No finalize tx; simplified mint args.

Summary — what's built

  • Contracts: TicketMinter — one tx: settle payment + mint ticket. Three settle modes: settleAndMintTicket (transferFrom), settleAndMintTicketEIP3009 (USDC-style transferWithAuthorization), settleAndMintTicketPermit2. ReputationRegistryV3 — giveFeedbackWithTicket{,For} on MINTED tickets; on-chain dedup; agent disputes; legacy giveFeedback reverts.
  • Python SDK: facilitator extension routes ExactEvmScheme.settle through TicketMinter when registered; resource-server extension rejects payloads without a bind (mint-required gate); client extension echoes the bind into PaymentPayload.extensions.erc8004; ERCFeedbackClient.submit_feedback_with_ticket (Path A) + submit_feedback_sponsored (Path B).
  • Verified: 14 Foundry tests + 63 Python unit tests + an end-to-end demo (run_ticket_demo.py) that forks mainnet, impersonates Circle / DAI-bridge whales for real USDC + DAI funding, registers an agent on the canonical IdentityRegistry, and runs 4 tickets through MINTED → CONSUMED.
Client — digests, payment sign, feedback (or sponsor auth) Agent server — 402, handler, optional receipt header Facilitator — verify, settle/mint gas; optional feedback relay gas Chain — TicketMinter, IdentityRegistry, ReputationRegistry
Ticket: NONE → MINTED (settle + job bind, one tx) → CONSUMED (feedback)

Smart contracts

TicketMinter new
settleAndMintTicket(payer, agentId, requestHash, interactionHash, endpoint) — facilitator submits with payment auth in the same tx. On success: transfer + MINTED ticket + TicketMinted event. Revert ⇒ no ticket.
Recovery: ticketId from PAYMENT-RESPONSE extension, or from mint tx receipt via TicketMinted (standard x402 tx hash).

IdentityRegistry
Unchanged — ownerOf(agentId) for payTo binding and receipt/dispute auth.

Feedback submission — gas paths

A — Client-paid (default) Client EOA sends giveFeedbackWithTicket(...) directly. msg.sender == payer. Client pays gas.
B — Facilitator-sponsored Client signs an off-chain FeedbackIntent (EIP-712): ticketId, feedbackHash, value, endpoint, nonce, deadline. Facilitator submits giveFeedbackWithTicketFor(payer, …, signature) and pays gas. Registry verifies signature → attributes to payer, not facilitator. Same dedup/consume rules.

Key considerations

  • No finalize tx. Job binding is complete at mint (requestHash + interactionHash + endpoint). Response proof stays off-chain (HTTP body + optional X-X402-Interaction-Receipt) unless the client embeds it in feedbackHash / feedbackURI.
  • No IPFS required. Composable contracts read the ticket; rich text is optional via feedbackURI.
  • interactionHash vs agent receipt. interactionHash is a content commitment computed by the client (table above). The agent receipt is a separate optional signature over receipt_digest(chainId, ticketId, interactionHash) — it attests “I served this job,” not the same bytes as interactionHash.
  • Singleton choke point. One successful settle ⇒ one ticketId. Buyer still submits (or signs for) feedback; registry gates on ticket consume.
  • No tx hash on ticket. Settlement tx hash stays in standard x402 PAYMENT-RESPONSE and off-chain artifacts only; use it to recover ticketId from the mint receipt when needed.

Phases (one paid HTTP request)

0 — Discover client agent server x402

Client GET /resource → agent server returns 402 + extensions.erc8004.agentId, accepts. Client learns endpoint (this URL).

1 — Bind job (off-chain) client

Client computes requestHash and interactionHash (see table). Echoes them in PaymentPayload.extensions.erc8004 for the facilitator/minter.

2 — Sign payment client x402

Standard x402: client signs token authorization from PaymentRequired (EIP-3009 / Permit2 / ERC-20).

3 — Paid retry client agent server facilitator x402

Client retries same URL with X-PAYMENT. Agent server → facilitator verify → settle.

4 — Settle + mint (one chain tx) facilitator chain on-chain

Facilitator: settleAndMintTicket{,EIP3009,Permit2}(payer, agentId, requestHash, interactionHash, endpoint, …). Ticket MINTED. Facilitator pays gas. If mint reverts, settle returns success=false and the framework surfaces it as a settle failure to the caller (no ticketId on PAYMENT-RESPONSE).

Pre-handler gate: the resource-server extension's after_verify hook refuses payloads that don't carry the bind fields (requestHash, interactionHash, endpoint, agentId) — without a bind the ticket can't be pinned, so the paid handler is skipped before any tokens move.

5 — Serve resource agent server x402

Handler runs after mint. Builds HTTP response; optional X-X402-Interaction-Receipt (agent signs receipt digest — see hash table). No chain tx.

6 — HTTP response agent server client x402

200, body, PAYMENT-RESPONSE (txHash, payer, ticketId). Optional receipt header.

7 — Feedback (later) client facilitator chain on-chain

Path A: client giveFeedbackWithTicket (client gas). Path B: client signs intent → facilitator giveFeedbackWithTicketFor (facilitator gas). Requires MINTED ticket; consumes ticket.
