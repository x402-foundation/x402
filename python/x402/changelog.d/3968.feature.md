Added multi-payee splits to the SVM `exact` scheme (`extra.splits`, `ataCreationRequired`). The client builds one `TransferChecked` per leg plus fee-payer-funded `CreateIdempotent` for marked recipients, and accepts valid splits by default. The quoted total can pay multiple recipients; applications can screen them through the core `on_before_payment_creation` hook before signing. The server rejects split terms the facilitator does not advertise. The facilitator advertises `maxSplits` / `ataCreationSponsored` only when configured with `max_splits` / `ata_creation_sponsored` and verifies split charges on the static layout. Split charges work on transaction versions 0 and 1.
