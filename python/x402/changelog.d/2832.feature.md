Add an opt-in `omit_optional_payload_fields` flag to `FacilitatorConfig` that strips the optional `resource` and `extensions` fields from the payment payload before it is POSTed to the facilitator. This keeps `verify`/`settle` working against facilitators that validate the payload against a strict schema and reject those optional fields. It is off by default, so the full spec-compliant payload is sent unless a caller explicitly enables it.
