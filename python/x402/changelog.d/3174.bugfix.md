Fixed the facilitator (V1 and V2) settling and verifying EIP-3009 payments against `requirements.asset` unconditionally, ignoring a seller-supplied `extra["verifyingContract"]`. Trusting `extra.verifyingContract` is opt-in via a `verifying_contract_validator` callback passed to `ExactEvmSchemeConfig`/`ExactEvmSchemeV1Config`; by default (no validator supplied) verification and settlement still always use the asset address, matching prior behavior.
