Failures before the facilitator is reached during settlement (a `before_settle` abort or throw, or a settlement payload enrichment error) now dispatch `settlement_preflight_failed` cancellation to `on_verified_payment_canceled` hooks and the scheme's `settle_on_cancel`, then re-raise the original error. No cancel is dispatched for an after-handler settle on a flow that already settled before the handler. `VerifiedPaymentCanceledContext` and `VerifiedPaymentCancelOptions` gain an optional `verify_result`, set for `after_verify_aborted`. **Behavior change:** `on_settle_failure` hooks now run only once the facilitator was reached, matching the TypeScript and Go SDKs. `VerifiedPaymentCancellationReason` gains `settlement_preflight_failed`.
