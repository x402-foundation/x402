Fixed the exact SVM facilitator's Path 1 (static layout) verification rejecting valid Phantom-signed payments when Phantom injects Lighthouse assertion/guard instructions before the compute budget/`TransferChecked` sequence instead of strictly after it. Path 1 now classifies each instruction by identity (program ID + discriminator) rather than fixed position: protocol instructions (compute limit, compute price, transfer, optional memo) must still appear in that relative order, but Lighthouse guard instructions — which only assert and abort, never mutate state — are accepted anywhere in the instruction list with no upper bound. This is purely additive: old-style payloads (Lighthouse only after the transfer, within the previous instruction-count bounds) still validate, and no existing error constant was renamed or removed.
