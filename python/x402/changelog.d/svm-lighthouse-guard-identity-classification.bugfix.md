Fixed exact SVM Path 1 rejecting Lighthouse assertion guards before the compute-budget/TransferChecked sequence or beyond Python's old six-instruction cap. Identity classification preserves protocol relative order while permitting assertions anywhere without a count cap. Only assertion discriminators 2..=17 are guards, and every guard must isolate the facilitator fee payer. MemoryWrite, MemoryClose, empty data, and unknown variants are rejected without smart-wallet fallback; previously accepted unsafe Lighthouse instructions are intentionally rejected. Configured preflight/postflight blocks cannot hide top-level TransferChecked instructions; their CPI effects remain operator-trusted. Existing error constants remain exported, but Path 1 no longer emits invalid_exact_svm_payload_transaction_instructions_length or invalid_exact_svm_payload_unknown_{fourth,fifth,sixth,seventh}_instruction. Callers branching on those strings must handle invalid_exact_svm_payload_unknown_instruction and invalid_exact_svm_payload_transaction_instructions_order instead.
