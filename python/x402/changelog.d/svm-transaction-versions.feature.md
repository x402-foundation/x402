SVM facilitators now advertise the transaction message versions they accept as `extra.transactionVersions` (`[0]`) in `/supported`; servers copy it into `PaymentRequirements.extra`, and clients fail fast with `unsupported_transaction_version` when version 0 is not among the advertised versions. Verifiers reject any message version they do not model with `unsupported_transaction_version` before inspecting instructions; legacy messages remain accepted for backward compatibility but are deprecated and never advertised.
