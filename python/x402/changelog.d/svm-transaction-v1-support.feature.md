SVM exact payments now accept transaction version 1 (SIMD-0385). Version 1 carries its compute budget and priority fee in `message.config` instead of ComputeBudget instructions, so the facilitator reads the budget from there, requires `computeUnitLimit` and `loadedAccountsDataSizeLimit`, and normalizes the total-lamport priority fee against the per-compute-unit cap (`priorityFeeLamports * 1e6 <= maxPriorityFeeMicroLamports * computeUnitLimit`). The version 1 static layout is a TransferChecked at instruction index 0 followed by up to four Lighthouse/Memo instructions; a ComputeBudget instruction inside a version 1 transaction is rejected. Transaction versions are now checked against an allowlist before any instruction is inspected, so a version this code does not model is rejected with `unsupported_transaction_version` rather than passing a compute budget scan vacuously. The legacy x402 v1 wire scheme is index-based over the compiled message and gates version 1 rather than supporting it.
