Python client selection and resource servers now resolve a scheme registered
under a network pattern (for example `eip155:*`) when the same network also has
an exact registration for a different scheme. Previously the exact network's
scheme map hid the pattern scheme, so an `upto` payment on `eip155:1` failed
with `NoMatchingRequirementsError` and a route that used it raised
`SchemeNotFoundError`.
