Add the Starknet `exact` scheme reference implementation (TypeScript), following `specs/schemes/exact/scheme_exact_starknet.md`. The client builds and signs a SNIP-9 v2 `OutsideExecution` authorizing exactly one SNIP-2 `transfer`, bound to the sponsor through `Caller = extra.feePayer`, so the payer never needs gas and never contacts the facilitator. Includes the client, resource-server, and facilitator schemes for `starknet:SN_MAIN` and `starknet:SN_SEPOLIA`: canonical SNIP-12 typed-data reconstruction before hashing (never the client's own `typedData`), caller binding, single-call and exact-amount enforcement, the `Execute Before` freshness band plus minimum-remaining-window floor, onchain `is_valid_signature` / `is_valid_outside_execution_nonce` / balance preflight, and mandatory `starknet_simulateTransactions` that fails closed unless the trace shows exactly the expected asset `Transfer`. Settlement re-verifies, guards duplicate submissions, and reports success only on a `SUCCEEDED` receipt that actually emits that transfer, with a non-terminal `settlement_pending` outcome when confirmation is indeterminate and consumed-nonce reconciliation for a payment that already landed. The scheme declares the `authorization` payment flow and has no on-wire `assetTransferMethod`, so it registers under core's `default` ATM sentinel and the 402 wire format is unchanged. Default assets follow the shared per-family convention: `DEFAULT_ASSETS` (Circle USDC on both networks) with `getDefaultAsset` / `findDefaultAsset`, so `"$0.10"` and `"0.10 USDC"` prices resolve through core's `parseMoney`, and the client scheme exposes `findDefaultAsset` so `x402Client` spend controls recognize USDC as a USD-pegged default. `starknet` v8 is a peer dependency - the only release line supporting both RPC spec 0.8.1 and 0.9.0, since v7 cannot broadcast against a 0.9.0 node and v9+ drops 0.8.1.
